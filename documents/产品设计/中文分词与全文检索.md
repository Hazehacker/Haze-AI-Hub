# Zhparser 中文分词全文检索设计

## 1. 背景与目标

**问题**：当前项目中 PostgreSQL 全文检索使用 `simple` 分词器，对中文按空格/标点机械切分，无法实现真正的中文分词（如"人工智能平台"→"人工智能"+"平台"），导致 BM25 检索质量极差。

**目标**：在文档**存储时**使用 `zhparser` 进行中文分词，建立优化过的 `tsvector` 全文索引，替代现有的查询时采用 `simple` 分词的做法。

## 2. 技术方案

### 2.1 PG 扩展选型

| 方案 | 分词器 | 优点 | 缺点 |
|------|--------|------|------|
| zhparser | SCWS | 轻量、易装 | 效果一般 |
| pg_jieba | Jieba | 效果最好 | 需编译 |
| **推荐** | **zhparser** | 安装最简、已验证 | 满足中文检索需求 |

### 2.2 架构设计

```
写入流程（新增）:
  KbChunk.content (原始文本)
       ↓
  调用 zhparser 分词服务
       ↓
  生成 to_tsvector('zhcfg', content)
       ↓
  存入 kb_chunk.search_vector 字段

查询流程（不变）:
  用户查询 → plainto_tsquery('zhcfg', query)
       ↓
  WHERE search_vector @@ plainto_tsquery(...)
```

### 2.3 数据库改动

**新增列**：

```sql
ALTER TABLE kb_chunk ADD COLUMN search_vector tsvector;
CREATE INDEX idx_chunk_search_vector ON kb_chunk USING GIN (search_vector);
```

**修改 KbChunkMapper.xml**：

- `add` 时：调用 SQL 函数生成 `search_vector`
- `bm25Search` / `hybridSearchRrf`：改用 `search_vector` 替代 `to_tsvector('simple', content)`
- 保留 `simple` 分词的 fallback 逻辑（`search_vector` 为空时降级）

### 2.4 关键组件

| 组件 | 职责 |
|------|------|
| `ZhparserTokenizer` | 调用 zhparser 生成 tsvector |
| `KbChunkMapper.xml` | SQL 层新增 search_vector 写入和检索 |
| `HybridVectorStore` | 新增 `addWithTokenizer` 方法，支持分词入库 |

### 2.5 错误处理

- zhparser 不可用时：降级到原有 `simple` 分词逻辑，`search_vector` 为 NULL，走原有 `to_tsvector('simple', content)` 逻辑
- 分词服务异常：记录日志，抛出业务异常

## 4. 风险

- PG 版本兼容性：zhparser 需要 PG 10+
- 云 PG 支持：阿里云RDS/腾讯云等不一定支持编译安装 zhparser
- 存量数据：需要提供迁移脚本重新生成分词向量
