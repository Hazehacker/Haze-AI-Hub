# 线程池参数设置

## 概述

项目使用 Spring 异步任务线程池处理 IO 密集型操作，主要场景包括：
- AI 接口调用（网络 IO）
- PostgreSQL 数据库读写
- 异步标题生成

## 参数计算公式

基于服务器 CPU 核心数动态计算：

```
corePoolSize = CPU核心数 * 2
maxPoolSize = CPU核心数 * 8
```

## 具体参数

| 参数 | 值 | 说明 |
|------|-----|------|
| corePoolSize | CPU核心数 * 2 | 核心线程数，常驻线程 |
| maxPoolSize | CPU核心数 * 8 | 最大线程数 |
| queueCapacity | 200 | 任务队列容量 |
| threadNamePrefix | title-gen- | 线程名称前缀 |
| waitForTasksToCompleteOnShutdown | true | 关闭时等待任务完成 |
| awaitTerminationSeconds | 60 | 关闭时最大等待时间 |



假设服务器为 8 核 CPU：

| 参数 | 值 |
|------|-----|
| corePoolSize | 16 |
| maxPoolSize | 64 |
| queueCapacity | 200 |

## 设计思路



### 为什么 maxPoolSize 是 corePoolSize 的 4 倍

对于 IO 密集型任务，线程大部分时间在等待 IO 完成（非 CPU 计算），因此可以配置更多线程来提高并发度。

- **核心线程数 (corePoolSize)**: 设置为 CPU 核心数的 2 倍，确保日常负载下有足够线程
- **最大线程数 (maxPoolSize)**: 设置为 CPU 核心数的 8 倍，应对突发高并发
- **队列容量 (queueCapacity)**: 200，缓冲等待处理的任务



## 注意事项

1. **内存考虑**: 每增加一个线程约占用 1MB 栈空间，按 maxPoolSize=72 计算约额外占用 72MB
2. **队列选择**: 当前使用 LinkedBlockingQueue（容量200），任务积压超过队列会创建新线程直到 maxPoolSize
3. **优雅关闭**: 配置了 shutdown 等待，确保异步任务不会丢失
