# 消息队列双方案设计文档

## 1. 背景

Astra 知识库模块的文件解析任务原来使用 **Redis Stream** 实现异步消息队列。为了解学习 **RocketMQ** 的使用方式，同时保持原有功能稳定，设计了消息队列抽象层，支持 **Redis Stream** 与 **RocketMQ** 两种方案可通过配置切换。

## 2. 架构设计

### 2.1 整体架构

```
                          ┌─────────────────────────────┐
                          │    ParseTaskProducer        │  (接口)
                          │    ParseTaskConsumer        │  (接口)
                          └─────────────────────────────┘
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                                       ▼
        ┌───────────────────────┐           ┌───────────────────────┐
        │   RedissonStream       │           │      RocketMQ         │
        │   (type=redis)        │           │   (type=rocketmq)     │
        ├───────────────────────┤           ├───────────────────────┤
        │ RedissonStreamProducer│           │   RocketMQProducer     │
        │ AstraParseConsumer    │           │   RocketMQConsumer     │
        └───────────────────────┘           └───────────────────────┘
```

### 2.2 消息流对比

#### Redis Stream 方案
```
文件上传 → RedissonStreamProducer.sendParseTask()
        → Redis Stream (astra:parse:queue)
        → AstraParseConsumer 消费循环 (XREADGROUP)
        → 工作线程池处理解析
        → XACK 确认消息
        → 失败: 指数退避重试 → DLQ
```

#### RocketMQ 方案
```
文件上传 → RocketMQProducer.sendParseTask()
        → Topic (astra-parse-topic)
        → RocketMQConsumer 消费 (PushConsumer)
        → 工作线程池处理解析
        → 自动 ACK
        → 失败: 指数退避重试 → DLQ Topic
```

## 3. 核心接口设计

### 3.1 ParseTaskProducer (消息生产者接口)

```java
public interface ParseTaskProducer {
    /**
     * 发送解析任务到主队列
     */
    void sendParseTask(ParseMessage message);

    /**
     * 发送消息到死信队列
     */
    void sendToDlq(ParseMessage message, String error);
}
```

### 3.2 ParseTaskConsumer (消息消费者接口)

```java
public interface ParseTaskConsumer {
    /**
     * 启动消费者
     */
    void start();

    /**
     * 关闭消费者
     */
    void shutdown();

    /**
     * 获取消费者名称
     */
    String getConsumerName();
}
```

## 4. 关键概念对应

| Redis Stream | RocketMQ | 说明 |
|-------------|----------|------|
| Stream (List) | Topic | 消息主题 |
| Consumer Group | ConsumerGroup | 消费者组 |
| `XREADGROUP` | `DefaultMQPushConsumer` | 拉取并消费模式 |
| `XACK` | 自动 ack | 消费确认机制 |
| DLQ (独立 Stream) | 另一个 Topic | 死信队列 |
| `neverDelivered` | 新建 ConsumerGroup | 只消费新消息，避免重复 |

## 5. 配置切换

在 `application.yaml` 中修改 `astra.mq.type` 即可切换：

```yaml
# 方案一: Redis Stream (默认)
astra:
  mq:
    type: redis
  redis-stream:
    queue-name: astra:parse:queue
    dlq-name: astra:parse:dlq
    consumer-group: astra-parse-group
    max-retries: 3
    retry-delay-ms: 5000

# 方案二: RocketMQ
astra:
  mq:
    type: rocketmq
  rocketmq:
    namesrv-addr: localhost:9876
    parse-topic: astra-parse-topic
    dlq-topic: astra-parse-dlq
    consumer-group: astra-parse-consumer-group
    producer-group: astra-parse-producer-group
    max-retries: 3
    retry-delay-ms: 5000
```

## 6. 实现细节

### 6.1 Redis Stream 实现

**RedissonStreamProducer**
- 使用 Redisson 的 `RStream` API
- `stream.add(StreamAddArgs.entries(fields))` 发送消息
- 死信消息发送到独立的 DLQ Stream

**AstraParseConsumer**
- 三级线程池架构:
  1. 消费循环线程 (单线程，专职拉取)
  2. 解析工作线程池 (弹性扩缩容)
  3. 重试调度器 (延迟指数退避)
- `readGroup(neverDelivered)` 确保只处理从未投递的消息
- 失败时 `schedule` 延迟重新入队

### 6.2 RocketMQ 实现

**RocketMQProducer**
- 使用 `DefaultMQProducer`
- 消息体为 JSON 序列化的 `ParseMessage`
- 通过 `putUserProperty` 传递重试次数等元数据
- 死信消息发送到独立的 DLQ Topic

**RocketMQConsumer**
- 使用 `DefaultMQPushConsumer` (Push 模式消费)
- 实现 `MessageListenerOrderly` 接口
- 工作线程池处理实际解析
- 重试调度器实现指数退避

## 8. RocketMQ 部署准备

切换到 RocketMQ 方案前，需要先创建 Topic 和消费者组：

```bash
# 进入 RocketMQ bin 目录
cd rocketmq-all-5.3.2/bin

# 创建解析任务 Topic
mqadmin updateTopic -n localhost:9876 -t astra-parse-topic -c DefaultCluster

# 创建死信 Topic
mqadmin updateTopic -n localhost:9876 -t astra-parse-dlq -c DefaultCluster

# 创建消费者组
mqadmin updateSubGroup -n localhost:9876 -g astra-parse-consumer-group -c DefaultCluster
```

## 9. 设计要点总结

1. **接口抽象**: 通过 `ParseTaskProducer` / `ParseTaskConsumer` 接口解耦
2. **配置驱动**: `@ConditionalOnProperty` 根据配置决定加载哪个实现
3. **功能对等**: 两种方案实现完全相同的功能 (发送、消费、重试、DLQ)
4. **学习导向**: RocketMQ 实现保留了与 Redis Stream 相同的概念映射，便于理解
5. **弹性线程池**: 工作线程池与消费线程分离，支持独立扩缩容
6. **指数退避**: 重试采用 `delay * 2^retryCount` 策略，避免频繁重试

## 10. 适用场景

| 方案 | 适用场景 |
|-----|---------|
| Redis Stream | 已使用 Redis、项目规模较小、追求简单部署 |
| RocketMQ | 需要更高吞吐量、已部署 RocketMQ、需要事务消息等高级特性 |
